# 游戏包-官方动态背景接入-交接

日期：2026-11-15　状态：**已完成，端到端实测通过**

## 背景

官方启动器主界面有一段动态背景视频（换版本会换）。此前包只声明了静态 `assets.background`（background.webp），主页铺的是静态图。参照库 `Hi3Helper.Plugin.Hypergryph-main`（Collapse 终末地插件）的 `HgLauncherApiMedia.cs` 里有 `get_main_bg_image` 实现，本轮把它接入包 provider 并打通宿主渲染链。

架构裁定（AGENTS.md 红线不变）：**包出游戏语义（端点/码/字段），宿主只认通用 URL**。

## 实测结论（2026-11-15，双服通过）

- 端点与公告同一条：`POST {LAUNCHER_CHANNELS[server].url}`（web/batch_proxy）。
- **请求体必须带 `platform:"Windows"` + `source:"launcher"`**，否则返回 200 但 `proxy_rsps` 里只有 `{"kind":"get_main_bg_image"}` 空壳、没有 rsp 数据——插件源码里这两个字段是 HgCommonReq 的默认值，交接文档此前只记了 appcode/channel/language，漏了这两个，第一轮真打空返回就是这么来的。
- 请求：`{"seq":"<通道seq>","proxy_reqs":[{"kind":"get_main_bg_image","get_main_bg_image_req":{appcode, language, channel, sub_channel, platform, source}}]}`，与 `get_banner` 的 common 完全同构。
- 响应：`proxy_rsps[].get_main_bg_image_rsp.main_bg_image.{url, video_url, md5}`；`url` = 海报 webp，`video_url` = 背景视频 mp4。
- 国服（CN，appcode `6LL0KJuqHBVz33WK`，channel 1/1，language zh-cn）：视频 18,610,791 B + 海报 4,520,274 B，CDN `hg-utils-public.hycdn.cn`。
- 国际服（GL，appcode `YDUTE5gscDZ229CW`，channel 6/6）：视频 18,610,791 B（同一段）+ 海报 4,711,826 B，CDN `gl-utils-public.hg-cdn.com`。
- 通道码不对（GL 用 1/1）同样只回空壳——与公告「接口 200 但内容全空」同一表现。
- 视频内容与语言无关（背景本身无语言维度），provider 不吃 lang 参数。

## 实现行为

**包侧**（`provider.py`）：

- 新增 `method_background(params)`：复用 `notice_channel` / `notice_language` 选通道，一次 POST 返回通用字段 `{"video": <mp4 url>, "poster": <海报 url>}`；空壳返回抛 `ProviderError("背景接口没有返回视频地址。")`。
- `METHODS` 注册 `background`，`ping.capabilities` 加 `background`。
- 协议文档已更新：Arietta 仓库 `docs/游戏包-Provider协议-交接.md` 方法表加了一行。

**宿主侧**（换包零改动，两处通用能力 + 一处根因修复）：

- `DynamicBackgroundStore.CheckAndUpdateAsync`：背景来源统一成通用三字段 `BgSource(video, poster, id)`——库洛两款走自家接口（原分支不动，slogan 版本名图层是库洛专属），包游戏走 `GamePackService.RunProviderAsync(pack, "background")`（`GetPackSourceAsync`，超时 90s）。版本比对仍用 meta 的 source URL（官方 CDN 每版一个 md5 文件名，换版必换 URL）；下载/缓存/清理/`Updated` 事件全链复用，缓存落 `bg\External\`（`bg-{id}-{时间戳}.mp4` + `poster.webp` + `meta.json`）。`SyncAllAsync` 在当前游戏是包时把 External 排进同步列表（库洛两款照常）。
- `KuroLauncherBackgroundClient.GetSourceBiz`：**根因修复**——原兜底 `_ => WutheringWaves` 会把 External（包游戏）当鸣潮，导致 `CanFetch(External)` 误判 true、宿主把**鸣潮的背景**下载进 `bg\External` 铺到终末地主页（2026-11-15 03:34 实踩）。现在 External 原样返回 → `CanFetch(External)=false` → 走包分支。
- 主页表现：`BackgroundGallery.Resolve` 缺省回落顺序是官方动态背景 > 包自带背景，官方背景下载完成（`Updated` 事件）后主页自动切到视频，海报做首帧占位 + 主题色取色源（实测从终末地海报取到金色 #FFB29247）；包背景无版本名图层，slogan 层自动隐藏（`ShowDynBgSlogan_External` 默认 0，且 `GetSloganPath(External)` 找不到文件返回 null）。

## 验证方式

```bash
# 双服直测（仓库或部署副本目录下）：
echo '{"id":1,"method":"background","params":{"server":"CN"}}' | python provider.py
echo '{"id":2,"method":"background","params":{"server":"GL"}}' | python provider.py

# 端到端：删冷却键 → 启动开发实例 → 看缓存目录与日志
#   config.ini 删 DynBgLastCheck_v3_External=（6h 冷却，不清会 Skipped）
#   bg/External/ 应出现 bg-3e785e7f*.mp4（18,610,791 B）+ poster.webp（GL 4,711,826 B）+ meta.json，无 slogan.png
#   日志应有 "Kuro background External updated: 18610791 bytes"（走包分支，无 KuroLauncherBackgroundClient 取数日志）
```

2026-11-15 03:37 实测：全部符合预期，主页自动切到官方视频背景。

## 已知待办

- 多包共存：`GameRegistry.GetEntry(External)` 只认第一个包条目，`bg\External\` 目录与 `DynBgLastCheck_v3_External` 冷却键按 External 共享——第二个包接入前要先按 PackId 分目录分键（代码里已留 `ponytail:` 注释）。
- 包返回非 mp4/webm/mkv 的视频 URL 会被宿主拒收（`IsVideoUrl` 兜底）；仅图片的背景（video_url 缺失）暂不支持——`GetLocal` 以视频文件存在为前提，官方接口目前恒有 video_url。
- 开发实例里人工点一遍切换条 / 图库等 UI 细节未做（背景本体与自动切换已由日志 + 缓存文件验证）。
- 国际服当前下载的是 GL 通道的背景（跟随 `pack.ServerId` 当前激活服）；CN/GL 两服视频同一段、海报不同，切服后 6h 冷却内不会主动换，属可接受行为。
