# 本地化 · 硬编码中文盘点（2026-11-17）

## 背景

宿主有 10 语言翻译表（zh / zh-Hant / en / ja / ko / fr / de / es / th / pt-BR），包可经 game.json `strings` 的 `lang:键` 覆盖文案；带 `.zh-Hans` / `.zh-Hant` 后缀的键只对该语言生效，裸键全语言生效。宿主 `Lang.TryPackString` 的查表顺序：`lang:键.tag → 键.tag → lang:键 → 裸键 → 宿主当前语言表 → 宿主中文表`。本篇盘点包内所有没接上这套机制的硬编码中文。

## 实测结论（按用户可见程度排序）

| # | 位置 | 内容 | 严重度 |

## 机制缺口（想修也得先补的）

- 宿主 `GamePackService.RunProviderAsync` 不注入语言；`settings-model` params=null、`community-model` 只带 credential。**notice 已有 lang 透传先例**（provider.py 文档头 `{"method": "notice", "params": {"lang": "en", "server": "GL"}}`），照抄即可。
- 包侧修 #2 零代码依赖：裸键 → 加 `.zh-Hans` / `.zh-Hant` 后缀，其余语言自动回落宿主译文。

## 最懒修复路径（如果要修）

1. **game.json 裸键加后缀**（#2）：改 24 行 JSON，立刻恢复 8 语，收益最大成本最低。
2. **宿主 RunProviderAsync 自动注入 `lang`**（通用能力一处改动，所有方法受益；符合红线——宿主只传语言码不含游戏语义）。
3. **settings.cs / skland.py / provider.py 建 L10n 表**：照抄 gacha.py `_CHROME` 模式，按注入的 lang 查表，缺键回落简中。工作量主要在翻译条目本身（settings 约 100 条、skland/provider 约 60 条）。

## 验证方式

- `rg -c "[\p{Han}]" <文件>` 复查计数；切宿主界面语言到 English 打开抽卡/设置/社区页，看是否还有简中。
- #2 修后用 `Lang.Get("GachaLogPage_EmptyTitle")` 类键在 en 界面应返回宿主英文译文。
