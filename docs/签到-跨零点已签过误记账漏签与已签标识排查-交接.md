# 签到：跨零点「已签过」误记账漏签 + 已签标识不渲染 交接

日期：2026-11-17（凌晨～清晨排查）
关联：`docs/森空岛模块-游戏数据面板与H5进入实测-交接.md`、宿主 `PackCommunitySectionPage.xaml.cs`（签到卡渲染）、`GamePackCommunityAutoSignService.cs`（自动签到）

## 背景

用户报两件事：① 签到日历没有「已完成」标识（对照 Arietta 原生库街区 SignInPage 的画法）；② 「怎么没有启动 Arietta 就自动签到了」。排查中发现一个比两者都重的真 bug：跨零点误记账导致**整天漏签**；顺带挖出一个宿主渲染层的诡异 bug（TryGetBool helper 运行时失灵）。

## 实测结论

### 1. 已签标识不渲染：TryGetBool helper 运行时失灵（已修）

渲染代码、数据、二进制三层验证全部正确，但标识就是不出现：

- 模型：`skland.py` `_module_sign` 每个日历格带 `done`/`available`，缓存与实时 provider 输出均为真布尔（`"done":true`）。
- 渲染源码与反编译 IL 均正确：`BuildCalendar` 已签 = 内容淡化 0.55 + 右上 ✓ 角标（库街区同画法），下一个待领 = 主题色描边。
- **运行时探针（临时日志实测）**：同一元素、同一时刻——
  - `TryGetBool(day, "done")`（经 helper 传参）→ **False**，连续两次都 False；
  - `day.TryGetProperty("done", out el)`（直接读）→ **True**，`el.ValueKind==True`、raw=`true`。
  - 独立控制台复现同一解析逻辑 → helper 正常返回 True。Debug/Release 均复现，与 JIT 配置无关。
- **修复**：`BuildCalendar` 与 `BuildRewardChip` 的布尔全部改为内联直读 `element.TryGetProperty(...) && el.ValueKind == JsonValueKind.True`，删除 `TryGetBool` helper（无其他调用方）。
- **验证**：内联版实测——第 1~3 天淡化 + 右上金色 ✓、额外奖励 ✓ 全部正常渲染（宿主实时截图确认）。
- helper 失灵的根因未明（IL/源码/复现三方都查过），如未来在别处再遇到「helper 返回值与直接读不一致」，先怀疑同类问题。

### 2. 漏签真 bug：跨零点「已签过」被误记账（已修）

日志 00:02:00：`Pack auto sign-in ok: arknights-endfield 今日已签到`（官方回「已签过」）→ 宿主写 `GamePack_CommunityAutoSign_Last_arknights-endfield=20261117` → 当天所有启动/窗口显示触发都被 `doneKey == Today` 跳过，而日历显示当天实际未签。

根因：**签到端点的「已签过」判定与日历的「今天」跨零点边界错位**——23:5x 签的那次被端点算进「今天」，日历已翻到新的一天。原口径「已签过按成功算」在这种错位下把当天锁死。

修复（包侧 `skland.py`，端点语义不出包）：新增 `_calendar_signed(att)`（日历口径「今天已签」= `available==0 且 done>0`，`hasToday` 语义反直觉不单独用）；`sign_in` 遇官方「已签/重复/已领取」回话先 GET 日历核实，确认才 `ok=True`，错位时 `ok=False`「官方回已签过但日历未签，稍后自动补签」（宿主不记账，下次触发自动补）。

已知小噪音：错位窗口内每次触发会弹失败 toast 直到边界翻过去，可接受（好过静默漏签一整天）。

### 3. 「没启动就签」的澄清

自动签到只挂两个触发点：进程启动 + 主窗口每次显示，应用不运行没有任何写路径。日志里每条签到记录都对应一次应用会话（00:02 那次是应用开着跨零点、窗口显示触发）。

## 验证方式
