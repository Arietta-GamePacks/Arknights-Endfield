# 游戏包 · 抽卡统计模块接入 - 交接

> 时间：2026-11-15 凌晨
> 性质：**新模块落地**。包侧统计引擎 + 统计页 + provider 方法，宿主侧补通用 WebView 面板桥；宿主 Release 全量重建 0 错误，部署副本重签 `valid · PaperKito`。
> 前置：`docs/游戏包-GamePack首版与终末地接入-交接.md`（provider 字段预留）、`docs/森空岛API-数据终端直连实测-交接.md`（凭证链区分）、宿主 `docs/游戏包-Provider协议-交接.md`、`docs/游戏包-开发规范.md`。

## 一、为什么这一轮要做这些

调研宿主现状后的关键结论（本轮复查）：

- `provider` 通用 runner 早已有（`GamePackService.RunProviderAsync`），但宿主只消费 `notice` / `settings-model` / `background`，**`fetch` / `accounts` 没有消费端**；`GachaLogPage.OnLoaded()` 命中包游戏时直接 `ClearForPackGame()` 显示空页。
- `GamePack.Ui` 只是数据模型；`ui.community` 的通用 WebView 页（`PackCommunityPage`）由并行会话同期落地，但**没有 provider 脚本桥**，纯展示。
- 宿主原生抽卡统计（`GachaStatService` / `GachaLogViewModel`）强绑鸣潮：int `ResourceId`、固定卡池 1-13、固定 66/80/8/10 阈值、硬编码常驻 ID 表。`UgfService` 甚至只导入 `wuwa` 账号，字符串 `item_id` 落库会变 0。
- 结论：**不要改宿主数据库去兼容终末地**。按开发规范里 `ui` 的承诺做「包自绘面板」，宿主只补一个游戏无关的 WebView 容器 + 脚本桥。换任何游戏包宿主一行不用改。

## 三、架构边界（红线复核）

- **宿主零游戏知识**：新增的 `PackPanelPage` 只认 `ui.<panelId>`、`call(method, params)`、`state.get/set` 三类通用消息；`MainView.NavigateTo` 只判断「包是否声明了 `gacha` 面板」。宿主里没有终末地端点、appcode、卡池类型、保底数字、中文游戏词。
- **游戏知识全在包内**：`provider.py`（端点 / 凭证链 / 日志路径 / content 解析）、`gacha.py`（保底与统计口径）、`ui/gacha.html`（页面文案与编排）、`game.json`（面板声明）。
- 面板的 KV 缓存落在 `<宿主数据目录>/gamepacks/<packId>/<panelId>.state.json`，**不写包目录**——包目录每个文件都计入签名哈希。
- `provider.py` 开头设 `sys.dont_write_bytecode = True`，避免 `import gacha` 生成 `__pycache__/*.pyc` 污染签名哈希。

## 五、协议与报文

### provider 新增方法（协议仍为 1，老包零影响）

```
{"id":1,"method":"gacha-url","params":{}}
  → {"ok":true,"result":{"provider":"hypergryph","u8_token":"…","server_id":"1","channel":"…","uid":"…"}}

{"id":2,"method":"fetch","params":{"u8_token":"…","server_id":"1","provider":"hypergryph","lang":"zh-cn"}}
  → {"ok":true,"result":{"ugf":{…UGF v1.3…},
      "summary":{"uid","server","channel","nickname","records","provider",
                 "pool_info":{"<poolId>":{"up6_ids":[…],"pool_name","pool_type"}},
                 "rerun_counts":{"char":{…},"weapon":{…}}}}}

{"id":3,"method":"gacha-stats","params":{"ugf":{…},"pool_info":{…},"rerun_counts":{…}}}
  → {"ok":true,"result":{"model":{…通用渲染模型…}}}
```

- `fetch` 仍兼容原来的账号 token 模式（鹰角授权链 → u8_token），新增的直连模式只用于日志链接。
- `pool_info` / `rerun_counts` 放 `summary`，**不污染 UGF 文档本体**；两者拉取失败都静默降级（UP 标「未知」、大保底退回本地推断），不影响主流程。
- `gacha-url` 只在用户点「读取本地日志」时读 `%USERPROFILE%/AppData/LocalLow/{Hypergryph,Gryphline}/Endfield/sdklogs/HGWebview.log`，找不到返回可直接展示的中文提示。

### 脚本桥（宿主 ↔ 面板，游戏无关）

`window.Arietta`：

| 方法 | 消息 | 宿主行为 |
| --- | --- | --- |
| `call(method, params)` | `{id, kind:"call", method, params}` | `RunProviderAsync(pack, method, params, 120s)`，结果或 `error.message` 回传 |
| `state.get(key)` | `{id, kind:"state", op:"get", key}` | 读面板 KV，缺失返回 `null` |
| `state.set(key, value)` | `{id, kind:"state", op:"set", key, value}` | 写面板 KV（宿主数据目录） |

响应统一 `{id, ok, result | error}`；`key` / `packId` / `panelId` 都做 `[a-z0-9-]` 净化，面板相对路径做目录穿越校验。

## 六、统计口径（写在 `gacha.py` 文件头，此处摘要）

- 免费抽（`isFree`）计入总抽与稀有度，**不推进、不重置保底**；`gift*` 赠礼记录在 `build_ugf` 阶段已剔除。
- 角色：80 抽小保底（特许/重构跨池共享，基础/启程/辉光各自独立）；特许每池 120 抽必出 UP；重构 120 大保底按池名跨版本聚合，优先用官方累计次数（服务器权威，官方只保留 90 天明细）。
- 武器：40 / 80 保底按池独立，重构申领按 `pool_version` 分段；武库配额消耗按「同时间戳 + seq 连续」识别十连 × 1980。
- UP / 歪：`pool_info[poolId].up6_ids` 命中即 UP，未命中即歪；**缺 UP 名单时标「6★」而不臆断**，且整组只要有一个池缺名单就整组不判歪。
- 6★ 历史倒序展示，带「本抽是第几抽」、NEW、UP/歪/赠送、所属卡池与时间。
- 武库配额：角色池 4★=20 / 5★=200 / 6★=2000，总览给净值（产出 − 消耗）。

## 八、未验证 / 遗留

1. **未真打**：`/api/content`、`/api/record/{char,weapon}/rerun-counts`、`u8.<provider>.com/game/role/v1/query_role_list`、GRYPHLINE 抽卡域。本轮手里没有可用凭证，实现严格照两个现役参考库的字段与调用方式，且全部失败静默降级；需要真实账号跑一次 `fetch` 才能确认。
2. **端到端 UI 目验待用户**：切到终末地 → 左侧「寻访记录」→ 应出现统计页（演示数据）→ 填 token 或读日志 → 点「更新记录」→ 出真实统计。页面本身可用 `ui/gacha.html` 在浏览器离线预览。
3. 日志里的 `u8_token` 是短期凭证；账号 token 模式仍是推荐路径。两种凭证都只存在宿主数据目录的面板 KV，不写包目录、不进文档。
4. 增量同步未做：每次「更新记录」都是全量拉（分页有 0.28~0.65s 限速），记录多时偏慢。参考库用 `stopSeqId` 增量，后续可加。
5. `icons/` 立绘未在统计页展示（当前只有文字 + 稀有度分布），可以按 `game.json` 的 `icons` 约定补 `<item_id>.png`。
6. 仓库 `signature.json`、Release zip 待 assets 收尾统一处理。
