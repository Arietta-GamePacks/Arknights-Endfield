> **（2026-11-17 已归档：终态口径见 `森空岛H5-数据终端手机窗口-归档.md`；本文件保留逐轮实测与踩坑记录，冲突时以归档为准。）**

> 时间：2026-11-17 凌晨
> 性质：**新功能**。游戏数据面板新增「官方数据终端」入口，像库洛数据终端（鸣潮/战双）那样在
> 手机比例独立窗口里打开官方 H5 `game.skland.com/endfield/game-data`——推翻了
> `docs/森空岛模块-游戏数据面板与H5进入实测-交接.md` 「H5 是 PC 数据死路」的旧结论（那是裸开浏览器的结论，注入路径一直存在）。

## 一、机制逆向（2026-11-17，从页面 JS bundle 实测）

对象：`https://game.skland.com/endfield/game-data?header=0`（SPA，bundle 在 `assets.skland.com/_static_assets/game-tools/`）。
调查脚本与产物在包外 `build-out/h5-auth-hunt/`（页面 HTML + 4 个 bundle + 分析记录）。

| 环节 | 结论 |
|---|---|
| 进 App 流 | UA 含 `android` + `skland/<版本号>` 即判定 App 内打开（`SCHEMA_NAME='skland'`，`IS_ABROAD` 按 host 判定，game.skland.com 恒 false）；版本号从 UA 正则提取，参与桥目标的最低版本门（`environmentInfo` 2.0.0 / `openAuthenticationPage` 1.28.0，给 `skland/2.4.0` 全过） |
| 桥协议 | AndroidNative：`window.<SK目标>.<method>(params, callback)`，callback 收 **JSON 字符串**；找不到目标/方法抛 `no bridge api`。目标全集：SKPage / SKEnvironment / SKNavigation / SKModal / SKMessage / SKHandle / SKShare / SKPermission / SKNetwork / SKGame |
| 登录态 | 页面只调 `SKPage.userInfo` 取 `{code:0, cred}`（只要 cred 一个字段），塞进所有请求头；**其余 SK* 目标回 `{code:0}` 即可** |
| 签名 | 页面自己在 JS 里算（md5 + hmac + SHA256 四头，`dId`/`vName` 自理），会话 token 页面跟 `zonai /web/v1/auth/refresh` 自动换取/续期（401 code 10000 触发）——**宿主只需喂 cred，其余自理** |
| 数据端点 | 与 `skland.py` 真打过的同一批 `zonai.skland.com/web/v1/...`，同一个 cred（`_login` 产出） |
| 兜底路径 | 裸浏览器（非 App 流）认 URL `?code=&kind=` 走 `generate_cred_by_code`（会标 isAdmin，不用它）；HG 流另有 SDK 登录。均已绕开 |

未登录 + 非 App 流 = 下载引导墙（旧文档结论仍成立，只是不再是死路）。

## 二、实现行为

**架构判定**：完全复刻库洛数据终端三件套（App UA + 伪造桥 + 注登录态），但按红线宿主零游戏知识——
窗口只收 `{title, url, ua, script}` 四样通用参数，SK 桥应答 / cred 注入全在包内 script。

| 文件 | 改动 |
|---|---|
| 宿主 `Features/GamePacks/PackWebWindow.xaml(.cs)`（新增） | 通用「包手机窗口」：620×1140（库洛数据终端同尺寸）、UA 覆盖、script 以 `AddScriptToExecuteOnDocumentCreated` 随文档注入（先于页面脚本）、JS error/unhandledrejection 经 `postMessage('__packweb: …')` 回宿主日志（白屏排查用）、新窗口请求转系统浏览器、单例复用（再 Show 按新参数重建） |
| 宿主 `PackCommunitySectionPage.xaml.cs` | ① `links` 数组支持可选 `action` 字段：有则点击走 `community-action` 流程（渲染样式不变），无则维持外链；② `RunActionAsync` 识别结果里的 `webWindow` 对象 → `PackWebWindow.Show(title,url,ua,script)`，不走 InfoBar/刷新 |
| 包 `skland.py` | 新增 `web_terminal(token)`：`_login` 现算 cred → 拼注入脚本（10 个 SK* 目标 Proxy 应答，`SKPage.userInfo` 回 `{code:0, cred}`，cred 经 `json.dumps` 转义嵌入）+ H5 UA → 宿主 `webWindow` 形状。`_module_gamedata` 死键 `h5`（原生页从不消费）换成 `links:[{label:"官方数据终端", action:"h5-terminal"}]` |
| 包 `provider.py` | `community-action` 新分支 `h5-terminal`（带凭证校验，SklandError 转中文 message，其余照旧） |
| 宿主 `Arietta.csproj` | **根因修复（顺手）**：`Compile Remove="Arietta\log\**\*.cs"`——并行会话往运行日志目录丢反编译转储（`decompiled_section.cs`）时，SDK 通配把它编进工程，与真源码重复声明 `PackCommunitySectionPage` → 全工程 41 错（WMC0001 转换器连环 + WMC9999 编译器崩溃）。日志目录本就不该参与编译；并行会话的转储文件本身未动 |

凭证安全：cred 只在点击时现算现嵌，走 `community-action` 即时返回，**不进 `community-model.json` 缓存**（缓存仍零凭证）；不出日志。

## 二.6、桥补跳转语义（2026-11-17 凌晨第四轮，三打反馈）

三打：手机布局已对（shim 生效），但「能交互的很少」——「全部/更多」这类入口点了没反应。

根因：App 流里这些入口不走页面内路由，而是经桥让 App 开子页。bundle 里 `schema$2` 把 http 网址包成
`skland://web?url=<encodeURIComponent(url)>` 交 `SKNavigation.dispatch`（字符串参数），另有
`SKNavigation.openURL`（参数是 `{url}` 对象，AndroidNative 层 JSON.stringify 成字符串）。假桥只回 `{code:0}`，App 侧又不存在 → 表现为死点击。

修复（`skland.py` 注入脚本桥升级，仍只回不抛）：

| 桥调用 | 行为 |
|---|---|
| `SKNavigation.dispatch`（字符串深链） | 解出内层网址：同源 → `location.assign` 整页跳（注入脚本随文档重装，登录态不掉）；外域 → `window.open` → 宿主 NewWindowRequested → 系统浏览器；非网页深链（开游戏等）忽略 |
| `SKNavigation.openURL`（`{"url":…}`） | 同上 |
| `SKPage.pop`（H5 左上角返回箭头） | `history.length > 1` 时 `history.back()`，根页不动 |
| 其余 | 维持 `{code:0}` |

解码逻辑在浏览器实测：深链解包、外域判定、非网页深链透传全对。仅包侧改动，部署副本重签 `valid · PaperKito`。
已知残余：H5 内 App 专属弹层（`SKModal.alert` 类，App 渲染的确认框）仍不出现；点干员卡片若走路由则可用，走桥同理已覆盖。

## 二.7、pageInfo NaN 修复（2026-11-17 凌晨第五轮，四打反馈）

四打：子页跳转/交互通了，但详情页（影拓丰碑）顶部的系列切换标签**被标题栏挡住、无法交互**；手机上不重叠。

根因（bundle 精读 `getPageInfo`）：页面调 `SKPage.pageInfo` 拿 App 顶栏占位，拿到 `code==0` 后算
`top = Math.max(top, status_bar_height)`——我们的 `{code:0}` 不带字段，两个 `undefined` 参与运算
→ **`top = NaN`** → NaN 样式被 React 丢弃 → 粘性标签栏与 Header（`Wrapper$52 $paddingTop={top}`）
全部塌到同一位置。真机 App 回带数字的完整字段，故不重叠。

修复：桥对 `SKPage.pageInfo` 按**页面自己的 web 兜底形状**（`init_web$8` 的 getPageInfo）精确应答：
`{screen_width, screen_height, has_navigation_bar:false, navigation_bar_height:0, status_bar_height:0, top:0, left:0, bottom:0, right:0}`——页面对该形状有现成处理路径（独立浏览器里就是这个形状渲染的）。仅包侧改动，部署副本重签 `valid · PaperKito`。
教训：**假桥对每个 handler 都要回「字段完整的应答」**，空 `{code:0}` 遇到数值运算就变 NaN。

## 二.8、去掉激活重载（2026-11-17，五打反馈）

「移动窗口或点窗口外再回来都要重载一下，频率太高。」根因：照抄了库洛数据终端的 `Activated → ReloadAsync`
（它靠每次激活重载在切游戏/切账号时刷数据）。这里参数只随显式点击（Show）变化——改为**仅首次激活加载一次**
（`_shownOnce` 守卫），再次点击导航项仍会带新参数重载（显式动作，保留）。宿主改动，Debug/Release 双 0 错误。

## 三、验证方式

- 离线自检（`py -B`，stub `_login`）：`h5-terminal` 无凭证报「还没有森空岛凭证」、未知动作兜底、URL/UA/script 形状、cred 转义嵌入（`json.dumps` ensure_ascii 形式）、cred 不泄漏进 ua/title/url——全过。
- 构建：Release / Debug 双 0 错误（99 警告为既有）。
- 部署副本：`provider.py` / `skland.py` 已同步并重签 `valid · PaperKito`。
- **首打结果（2026-11-17 00:47，用户真机）**：窗口开了、UA 判定也过了（页面确实进了 App 流并调桥），但**桥应答没送达 → `bridge.call(SKPage_userInfo) timeout after 15000ms` 死循环，页面永远加载中**。根因（第二轮 bundle 精读）：AndroidNative 调 `window.<目标>.<方法>(params, callbackId)`——**第二参是 callbackId 字符串，不是函数**；应答必须经原生回调通道 `window.skland.callBack(callbackId, JSON串)` 送回（ABaseNative 构造时注册在 `window[SCHEMA_NAME]` 上），页面侧 JSON.parse 后 resolve。首版把第二参当函数等、`typeof cb==='function'` 恒 false，一个应答都没回。已修：`skland.py` 注入脚本改走 callBack 通道（带 `window.skland.callBack` 未就绪重试，50ms×20），同步重签。
- 顺手修宿主竞态：关窗瞬间 Activated 还会再触发一次重载，`AddScriptToExecuteOnDocumentCreated` 在已拆的 core 上炸（日志 00:53:51 那条 `Failed to open pack web window`）——`ReloadAsync` 加 `_closed` 守卫。
- **二打结果（2026-11-17 01:10 前后，用户截图 p1 vs App p2）**：数据全通了，但 p1 渲染成「缩小版 PC 页」，与 App 手机布局差距大。根因（IAB 实测 + bundle）：页面布局判定 `try{IS_PC=!document.createEvent('TouchEvent')}catch{IS_PC=!0}`——桌面 Chromium 无触屏支持，`createEvent('TouchEvent')` 直接抛 `The provided event type ('TouchEvent') is invalid`（IAB 413px 视口实测），页面判成 PC 走 PC 紧凑布局；真机 Android WebView 有触屏支持 → 手机布局。窗口尺寸其实没错：620 物理 px ÷ 150% DPI（AppliedDPI=144）= 413 CSS px，本就是手机宽度。**修复**：注入脚本垫 `document.createEvent` shim（TouchEvent 返回普通事件对象凑过真值检查），页面按手机布局渲染；仅包侧改动，重签部署副本。
- **端到端目验（待用户，第二轮）**：重启开发实例 → 终末地 → 森空岛 → 「游戏数据」→「官方数据终端」→ 应直接出 App 个人主页同款数据。若白屏：`Arietta_*.log` 搜 `Pack web JS`（页面 JS 报错）或 `Pack web page failed to load`。

## 四、已知边界与待办

1. **真打进展**：桥通了（二打出全量数据），布局 shim 刚落（等三打目验手机布局效果）。白屏/布局排查都有日志通道。
2. 桥内 `SKNavigation.openURL` / `openAuthenticationPage` 等一律回 `{code:0}` 不做事——H5 内的快捷入口深链点了没反应，属预期。
3. 窗口无返回/刷新按钮（H5 自带 header=0 无导航 chrome，右键菜单可刷新）；库洛窗口的「按激活刷新」行为一致（每次激活重载，顺带刷数据）。
4. 每次打开都现算 cred（grant + generate_cred_by_code 两 RTT ≈ 1s），未做缓存——登录态有效期内重复开销可接受，要省再加。
5. 仓库 `signature.json` 按既有口径等 assets 收尾统一重签。
6. 若 H5 改版（换桥协议/加版本门），只需改 `skland.py::web_terminal` 的 UA 版本号与脚本——宿主不动。
