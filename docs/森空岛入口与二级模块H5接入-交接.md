## 一、需求与结论

用户要求：「先增加一个森空岛入口，就是库街区改个名字而已；然后二级入口：每日签到（有现成图标）、危机合约、影拓丰碑、战争回响；官方有 H5，H5 入口也要做；图标用游戏数据的图标。」

**「只是改个名字」只对了一半**：导航项的名字确实能用包 `strings` 覆盖（零宿主改动），但宿主里 `GamePack.Ui` 字典此前**完全没有消费端**，包游戏也被 `UpdateNavVisibility()` 强制隐藏这个导航项，点进去是库洛专用的 `KuroBbsPage`。所以还需要一个通用面板容器 + 两处通用分支。

| 事 | 是否需要改宿主 |
|---|---|
| 把「库街区」显示成「森空岛」 | 不需要，包 `strings` 加 `lang:KuroBbs` 即可 |
| 让包游戏显示出这个导航项 | 需要（通用显隐条件：`Ui` 是否声明 `community`） |
| 点进去显示包自己的页面 | 需要（通用面板容器 + 改道分支） |

> **并行会话收敛**：本轮开发中，另一个会话已落地 `PackPanelPage`（通用面板容器，支持 `Arietta.call` provider 桥与 `Arietta.state` KV，按 `ui.<panelId>` 渲染任意面板，并把 `gacha` 接了进去）。本轮先写了一版 `PackCommunityPage`，发现功能重叠后**删除**，把 `community` 也改道到 `PackPanelPage`，避免留下两套容器。

**红线遵守**：宿主新增/修改的代码里没有任何游戏词、端点、图标路径。它只认 `Pack.Ui["community"]`、`Pack.Folder` 和 `lang:KuroBbs` 这个通用键；换任何游戏包一行不用改。

## 四、四个模块的数据（能拿到，实测）

全部来自同一个已验证的只读响应，**不需要登录 App**：

```
GET https://zonai.skland.com/web/v1/game/endfield/card/detail
    ?roleId=<binding.endfield.bindingList[].roles[0].roleId>
    &serverId=<roles[0].serverId>
    &userId=</api/v1/user/teenager 的 data.teenager.userId>
头：cred + sign（算法见前置文档）
```

| 模块 | 字段 | 实测内容 |
|---|---|---|
| 危机合约 | `data.detail.crisisContract[]` | 当期名称「危机合约 浸蓝测试作战」、`highest`/`challengeCount`、`weeklyMission`/`indicatorMission`/`stageMission` 进度、KV 图、起止时间戳 |
| 影拓丰碑 | `data.detail.indieHard.indieHardGroups[]` | 系列「深林呓语」、关卡组 `normalDungeon` / `hardDungeon` 的 `isPass`（关卡名虫傀呼应/受缚之影/相引之骸/怨怒延展，与公开攻略完全对上） |
| 战争回响 | `data.detail.warEchoes` 摘要 + `/api/v1/game/endfield/card/war-echoes` 完整数据 | `seasons`（狂热赛季等）、`weeks`、`dungeonGroups`、`bestRecord`、`achieves`、`activity` |
| 每日签到 | **只读** `GET /web/v1/game/endfield/attendance?roleId=&serverId=&userId=` | `calendar`（30 天 done/available）、`first`、`resourceInfoMap`、`hasToday`；签到领取是写操作，本包只读不代签 |

`data.detail.config.modules` 里能直接看到模块开关：`MODULE_CRISIS_CONTRACT` / `MODULE_WAR_ECHOES` / `MODULE_INDIE_HARD`（当前账号三项均为 `false`，但数据块照样返回，说明开关只控制展示）。

顺带确认：终末地的「危机合约」是终末地自己的玩法，不是明日方舟那个；四个二级入口全是终末地口径。

## 七、首次目验：点击「森空岛」闪退 → 已修复

**现象**：点左栏「森空岛」导航项，宿主进程直接退出（WER `APPCRASH`，`combase.dll 0x80004003` / `Microsoft.UI.Xaml.dll 0xc000027b`）。

**定位**：`src/Arietta/log/Arietta_261115.log` 里 `App_UnhandledException` 落盘的堆栈：

```
System.NullReferenceException
  at PackPanelPage.ShowFallback(...)  PackPanelPage.xaml.cs:318
  at PackPanelPage.OnLoaded()        PackPanelPage.xaml.cs:159
  at DispatcherQueueSynchronizationContext...Post()
```

并行会话新增的通用容器 `PackPanelPage.xaml.cs` **漏了构造函数 `InitializeComponent()`**。`PackWeb` / `Fallback*` 是 XAML 生成的字段（生成文件里带 `#pragma warning disable 0649`，所以编译期无警告），没初始化就是 null：`OnLoaded` 里 `PackWeb.EnsureCoreWebView2Async()` 抛 NRE → catch 调 `ShowFallback` → `PackWeb.Visibility` 再抛一次。`OnLoaded` 是 `async void`，二次异常无人接，进程结束。全项目其它 30+ 个 `PageBase` 派生页都调了 `InitializeComponent()`，只有这一页漏。

**修复**（只动宿主通用文件，无游戏知识）：补构造函数、`ShowFallback` 加 null 防御与日志、`OnLoaded` catch 记 warning、`NewWindowRequested` 用 `Uri.TryCreate` 挡非法 URI 并把 `Launcher.LaunchUriAsync` 切回 UI 线程（WebView2 回调不在 UI 线程，回调里抛异常会拖垮进程，也是点卡片跳 H5 时的潜在崩溃点）。

**验证**：`dotnet build src/Arietta.csproj -c Debug` → 0 错误（83 既有警告，覆盖用户实际运行的 `src/bin/x64/Debug/Arietta.exe`）；部署副本 `ui/community.html`、`ui/gacha.html` 均在，`GamePackSign verify = valid · PaperKito`。**包文件没改，无需同步或重签**；宿主需重启后复点一次。

## 八、订正：入口改为「库街区式侧栏 + API 数据面板」（本节为准）

**做错的地方**：第一版把二级入口做成了六个跳转官方 H5 的卡片，数据只在页面底部以文字说明字段。用户要的是**像库街区那样左侧二级导航、右侧直接显示 API 数据**，H5 只是附加入口；也不接受「PC 网页提取不到信息、还得靠 App」这个说法。前面涉及「只跳转 H5 / 数据未接入」的描述全部作废。

**实际数据能力（2026-11-15 真打，全程 PC 直连、不装 App、不 root、不抓包）**：鹰角 token → `grant(type 0, appCode 4ca99fa6b56cc2ba)` → code → `generate_cred_by_code` → cred + 签名密钥 → 6 个只读 GET。除前文的 `binding` / `teenager` / `card/detail` / `card/war-echoes`，**签到状态也有只读接口**：`GET /web/v1/game/endfield/attendance?roleId=&serverId=&userId=` 返回 `calendar`（30 天 `done` / `available`）、`first`（首签奖励）、`resourceInfoMap`、`hasToday`。`/api/v1/game/endfield/attendance` 同构可用；`.../sign-in`、`.../attendance/info` 均 404。签到领取是写操作，本包**只读展示、不代签**。

**落地结构**：

| 文件 | 内容 |
|---|---|
| `skland.py`（包内新增） | 全部森空岛游戏知识：端点、appCode、sign 算法（HMAC-SHA256 → hex → MD5，四头参与、时间戳回拨 5 秒）、字段映射、官方 H5 链接。`overview(token)` 一次拉齐四个模块，输出 `account` + `modules.{sign,crisis,monument,echoes}`，每个模块统一成 `cards` / `blocks`（rows + bars）/ `calendar` / `note` / `h5`。 |
| `provider.py` | 注册 `skland-overview`，`ping.capabilities` 加同名方法；把 `skland.SklandError` 转成可展示的中文 `error.message`。 |
| `ui/community.html`（重写） | 左侧 196px 二级导航（账号头像/昵称/等级、四个模块、分隔线、官方 H5、凭证设置，选中态黄色竖条）+ 右侧数据面板。`Arietta.call('skland-overview', {token})` 取数，`Arietta.state` 存 token 与 `skland.overview` 缓存；打开面板自动刷新一次，右上角「刷新数据」手动重拉；H5 链接全部 `target="_blank"`。 |

**红线**：宿主这轮**一行没改**——`PackPanelPage` 的通用 provider 桥已存在，端点/字段/图标全在包内；凭证落在宿主数据目录 `gamepacks/<pack>/community.state.json`，不进包目录、不影响签名哈希、不写日志。

**实测输出**（真账号，已脱敏到文档外）：账号 Lv60 / 26 干员 / 49 武器；签到日历 30 格；危机合约最高难度 1、挑战 1、周常 0/4、指标 1/5；影拓丰碑 8 系列 33 关（普通 33/33、苦难 9/33）；战争回响 1 赛季 + 轮换明细。`provider.py` 单行协议真打 `ok:true`，部署副本 `ping` 的 capabilities 含 `skland-overview`。

**验证**：`node --check` 两段脚本语法通过；两个图标路径存在；部署副本已同步 `provider.py` / `skland.py` / `ui/community.html`，`GamePackSign sign` + `verify` → `valid · PaperKito`。仓库 `signature.json` 仍按既有口径等 assets 收尾统一重签。

**已知边界**：`resourceInfoMap` 的奖励名映射按多种键容错，匹配不到时显示奖励 ID 尾号；`war-echoes` 的 `bestRecord` / `achieves` / `activity` 结构随赛季变化，已做类型容错；森空岛是未公开接口，改版需维护 `skland.py`。样式预览（脱敏快照 + 假桥）在包外 `build-out/community-panel-preview.html`。
