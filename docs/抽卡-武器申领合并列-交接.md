# 抽卡 · 武器申领合并列 · 交接（2026-11-16）

## 背景

终末地**每把限定武器都有专属申领池**（「幽寒申领」「细枝申领」……），一期武器一个池，
抽法为纯十连（点一次 = 10 抽）。原实现按 `poolId` 给每个申领各开一列，几期下来武器列
就溢出一屏。用户拍板：**只保留一个「武器申领」列**，以后任何新申领自动落进这一列。

第二轮修正（同日，用户逐条拍板）：

1. **界面上不出现申领名**——识别只用于算数，不用于显示；
2. **不显示「已垫」**——各申领独立保底且池会过期，合并列上放「已垫 N」等于暗示一个
   不存在的跨池保底进度；
3. **不用十连单位**，6★ 行直接记「第 N 抽」；
4. **武器申领保底 = 100 抽**（用户实测：第 10 次十连必得当期 UP）。

## 实测结论（机制口径）

- 每条武器记录自带 `poolId` / `poolName` / `poolVersion`，申领识别不依赖任何硬编码清单；
- **每个申领独立保底**，跨申领不能互相垫；重构申领同 `poolId` 复刻时按 `poolVersion`
  （期次）分段；
- **保底 100 抽出当期 UP**——这是用户游戏内实测口径（2026-11-16 口头拍板），
  参考库 `endfield-gacha-master/gachaCalc.ts` 的 `WEAPON_SMALL_PITY_MAX=40` /
  `WEAPON_BIG_PITY_MAX=80` 与之冲突，**按用户口径为准**（参考库疑似旧版数据）；
  若日后游戏内文案证实还有 40 档 6★ 小保底，改 `SMALL_PITY_WEAPON` 一处即可；
- `/api/record/weapon/pool` 返回只有 `poolId/poolName/poolType/online`，**不含保底规则**，
  保底数字只能人工维护。

## 实现行为（全部在包侧 `gacha.py`，宿主零改动）

| 点 | 行为 |
|---|---|
| 分组 | `winui_model` 武器记录不再按 `poolId` 分列，全部并入 `key="weapon"` 一列，列名「武器申领」 |
| 分段计数 | 新增 `_pool_changed()`：`poolId` 或 `poolVersion` 变化即视为新申领段；`pity_from_end` / `six_history` / `_rare_history` 加 `per_pool` 参数，行内「第 N 抽」在段内计数（跨段不累计） |
| 无已垫行 | 武器列 6★ 页签没有「已垫」首行（角色列保留，那里保底真实跨池共享）；无 6★ 时页签为空 |
| 无申领名 | 界面任何地方不出现申领名（第二轮拍板，第一版的「已垫 · 申领名」与 6★ 行前缀方案已撤销） |
| 保底刻度 | `SMALL_PITY_WEAPON = 100`；行条变红阈值 `pity_point = guarantee * 5 // 6`（80→66 / 100→83，与原写死值一致） |
| UP / 歪 | 武器列按**每条记录所属池自己的 UP 名单**判（`up_map`），老申领缺名单只影响自己那条（标「6★」）；角色列维持整组合判 |
| 免费 6★ | 不推进、不重置垫抽计数（探针断言：前 20 抽垫着 → 免费 6★ → 3 抽后出 6★，pity = 23 而非 3/24） |
| 6★ 平均 | `_avg_six` 加 `tail` 参数，尾部垫抽按申领分段取；旧申领收尾没出的垫抽会略微抬高均值（已留 ponytail 注释） |
| demo | 演示武器池改名「幽寒申领 · 演示期」、UP 武器「幽寒」 |

`analyze()`（HTML 预览 / `gacha-stats` 调试方法）武器侧仍按池出统计卡片（细分视角），
保底常量同步改为 100；宿主正式页只用 `gacha-model`（`winui_model`），不走它。
