## 一、结论速查

| 问题 | 结论 |
|---|---|
| 数据从哪来 | 只有一条：游戏内「寻访记录」页自己用的 H5 接口 `ef-webview.<provider>.com/api/record/{char,weapon}` |
| 用什么身份 | 森空岛 / 鹰角账号 token（`u8_token` 是它的下游产物），**抽卡页不再单独存 token** |
| 什么时候联网 | **只有用户点按钮时**。打开页面纯读盘，一个请求都不打 |
| 一屏几个卡池 | 固定 4 个，列宽等分铺满；第 5 个起横向滚动 |
| 武器申领列 | **所有申领合并成一列**（每把武器一个专属池），列内按申领名区分、保底按申领分段，见《抽卡-武器申领合并列-交接.md》 |
| 账号下拉显示什么 | 只有 UID，没有昵称、没有登录入口，写法逐字照抄鸣潮 `GachaLogPage` |
| UID 取哪个字段 | `bindingList[].roles[0].roleId`（终末地），**不是** `bindingList[].uid`（鹰角账号级） |

## 二、数据链路

### 2.1 拿 `u8_token` 的三条路

| 路 | 做法 | 现状 |
|---|---|---|
| **A 日志** | 读 `HGWebview.log` 里寻访页 URL 的 `u8_token=` 参数 | **主路径已死**：终末地 1.1 之后官方不再把寻访页链接写进日志。仅旧客户端 / 国际服还能用，保留作兜底 |
| **B 令牌链** | 账号 token → `oauth2/v2/grant`（appCode `be36d44aa36bfb5b`）→ `binding_list`（appCode `endfield`）→ `u8_token_by_uid` | **现行主路径**，就是社区登录那一份凭证 |
| **C 中转** | 转发第三方服务 | 不采用 |

### 2.2 接口

```
GET https://ef-webview.hypergryph.com/api/record/char
GET https://ef-webview.hypergryph.com/api/record/weapon
```

公共参数：`lang=zh-cn`、`token=<u8_token>`、`server_id=1`。
分页：`seq_id=<上一页最后一条的 seqId>`；返回 `data.list` + `data.hasMore`，**每页 5 条**。

- char 侧按 `pool_type` 拉（清单来自 `/api/content`）
- weapon 侧按 `pool_id` 拉（`poolType=rerun` 的复刻池要合并成一次 `pool_ids=a,b,c` 请求）
- 国际服域名走 `WEBVIEW_HOSTS[provider]`

### 2.3 两条凭证通道并行

`method_gacha_model` 里两条都试，先社区后日志：

1. 社区凭证 `credential` → 授权链 → u8 → 打接口
2. 失败或零记录 → 换日志 `u8_token` 再打一遍
3. 两条都挂 → 抛错，错误文案里带**两边各自的原因**

`summary.source` 会回报实际走的是哪条（`community` / `log`），网络拉取时模型里带 `channels` 数量。

## 三、凭证与 UID 口径

| 字段 | 是什么 | 用在哪 |
|---|---|---|
| `bindingList[].uid` | 鹰角通行证**账号级** uid（和明日方舟共用一个数字） | `u8_token_by_uid` 的请求体**必须用它**，显示绝不能用 |
| `bindingList[].roles[0].roleId` | **终末地 UID**（森空岛 App 个人主页那个数） | 账号下拉显示、UGF `account.uid`、缓存归属 |

> 踩过一次：显示用了账号级 uid，Alpha 一眼看出「这是明日方舟的 UID」。

日志通道（`gacha-url`）没有 binding，uid 靠 `u8/role/v1/query_role_list` 反查：
先按 `serverId` 匹配 `roles[].roleId` → 任意 role 的 `roleId` → 最后才回落 `data.uid`。

`CACHE_VERSION = 2`：v1 缓存里存的是错 uid，直接作废。

## 四、取数三档 + 本地缓存

宿主传 `mode`：

| mode | 触发 | 行为 |
|---|---|---|
| `cache` | 打开页面 / 切账号 | **只读盘**。无缓存 → 回 `needsSync` + 提示文案，不联网 |
| `incremental` | 「更新记录」/「从游戏日志读取」 | 用缓存里的 `max_seq` 当游标，`seqId <= stop` 立刻停 |
| `full` | 「全量重拉」/ 清空缓存后首次 | 从最新翻到最早，忽略游标 |

### 4.1 缓存文件

- 位置：宿主给的 `data_dir`（`<LocalFolder>/gamepacks/arknights-endfield/`）
- 文件名：`gacha-<凭证 sha1 前 16 位>.json`
- 为什么按凭证指纹而不是 uid：**uid 要联网才换得出来**，按 uid 命名就永远躲不开「打开即联网」
- 兜底：`load_only_cache()` —— 目录里只有一份缓存时直接用（只走日志通道的账号、凭证变过的账号靠它）

存的内容：`max_seq_char` / `max_seq_weapon` / `char` / `weapon` / `weapon_meta` / `pool_info` / `rerun_counts` / `updated`。

### 4.2 合并

`merge_pools()` 按 `seqId` 去重取并集 —— 增量只补新记录，历史一条不丢。
`pool_info`（UP 名单，判「歪」用）和 `rerun_counts`（官方累计寻访，重构池大保底）一并缓存，否则打开页面还得狂打 `/api/content`。

### 4.3 速度

- 卡池清单 + 各池翻页：`ThreadPoolExecutor(8)`
- 页间 `sleep 0.04~0.1s`（原来 0.28~0.65，太保守）
- `MAX_PAGES = 500`

**首次仍然慢**：每页 5 条，800 抽 ≈ 160 页。第二次起基本是几秒级。
要再快只能上「流式进度协议」，本次没做（见待办）。

## 五、宿主抽卡页 `PackGachaPage`

### 5.1 四列自适应

口径来自 `Arietta/docs/窗口-三档尺寸设置-交接.md`：**一屏固定 4 个卡池**。

```
列宽 = clamp(floor((ViewportWidth − 48 − 12×3) / 4), 240, 360)
```

- `ViewportWidth` 用 `ScrollViewer.ViewportWidth`（已扣竖向滚动条），布局未生效时退回 `ActualWidth`
- 48 = ItemsControl 左右各 24；12 = ItemsPanel `Spacing`
- 触发点：`SizeChanged`、`Pools.CollectionChanged`、模型应用收尾
- 三档参考值：大 313 / 中 283 / 小 263

> 曾经的 bug：`gacha.py` 里 `list(grouped.items())[:4]` 把第 5 个及以后的卡池直接吞了。已去掉，改为横向滚动。

### 5.2 账号下拉

逐字照抄鸣潮 `GachaLogPage`：

```xml
<ComboBox x:Name="Combo_Account"
          MinWidth="140"
          VerticalAlignment="Center"
          ItemsSource="{x:Bind ViewModel.Players, Mode=OneWay}"
          PlaceholderText="未登录"
          SelectedItem="{x:Bind ViewModel.SelectedPlayer, Mode=TwoWay}"
          SelectionChanged="Combo_Account_SelectionChanged" />
```

- `ViewModel.Players` = `ObservableCollection<string>`，**纯 UID 字符串**
- 没有昵称、没有登录入口、没有「未命名账号」占位
- 还没同步出 uid 的账号不进列表（也不给它编个名字兜底）
- `Dictionary<string,string> _uidToCredential` 做 UID → 凭证反查
- `_suppressAccountChange` 挡住 `ReloadAccounts` 重建列表时的「假切换」
- 切账号只切缓存视图（`mode=cache`），联网仍由按钮触发

### 5.3 设置面板（齿轮 → 「其他设置」Flyout）

照鸣潮不加 `Placement`，位置交给系统默认：

| 条目 | 行为 |
|---|---|
| 登录社区账号 | 包声明文案，宿主弹登录框，写回同一份 `community.json` |
| 从游戏日志读取 | 手动触发日志通道同步（`incremental`） |
| 全量重拉 | `mode=full` |
| 清空本地缓存 | 删该账号缓存文件（先确认） |
| 打开数据目录 | 打开 `gamepacks/arknights-endfield/` |

### 5.4 空态与提示

- `authRequired`：没凭证 → 画「登录社区账号」按钮 + 包给的理由文案
- `needsSync`：有凭证但没缓存 → 「点『更新记录』手动同步一次」
- 有数据时的报错走顶部 `InfoBar`（之前 `ErrorText` 根本没绑界面，报错看不见）
- 「同步中… 12s」实时计时，`DispatcherTimer` 每 250ms 刷一次

## 六、踩过的坑（按时间顺序）

1. **`HGWebview.log` 在 1.1 之后不再写寻访页链接** —— 社区脚本大面积失效，这也是「必须绑社区账号」的根本原因，不是优化。
2. **演示数据混进真实账号** —— 无凭证时回过 demo 模型，界面显示「演示数据 · 10000001」，Alpha 当场质疑。改为 `authRequired` 空态。
3. **`gacha.py` 只渲染前 4 个池** —— 第 5 个起被代码吞掉。
4. **`ErrorText` 没绑界面** —— 异常发生时界面一片空白，看不出出错。
5. **打开页面就自动同步** —— `mode=cache` 无缓存时退化成 full，还顺手探日志。改为纯手动。
6. **缓存按 uid 命名** —— uid 要联网才换得出来，与「打开只读盘」冲突。改按凭证指纹。
7. **uid 取错字段** —— `bindingList[].uid` 是账号级，显示出来是明日方舟的数字。终末地要用 `roles[0].roleId`。
8. **多写三个 ComboBox 属性导致弹层右偏** —— `Height="32"` + `Margin` + `DisplayMemberPath` + 对象项，实测浮层左缘比控件偏右约 6px。去掉后与鸣潮完全一致，偏移消失。
9. **擅自加需求** —— 修偏移时把 ComboBox 换成 Button+MenuFlyout，还往下拉里塞了「登录社区账号」。Alpha 明确要求收回，登录入口只留在设置面板与空态。
