## 一、为什么之前总览看不到 4★（根因）

上一轮已把总览收集范围放宽到 `rarity in (4, 5, 6)`，但列表尾部有 `[:20]` 张数上限、
按 `(-quality, name)` 排序——真实账号的 6★/5★ 名称数就够把 20 张占满，**4★ 永远排在被截掉的那段**。
demo 探针里能看到 2 张 4★ 纯属演示数据条目太少，掩盖了这个 bug。

## 二、最终实现

| 层 | 现状 |
|---|---|
| 卡池列分栏 | **维持两档 6★/5★**（4★ 分栏做过又撤了；宿主 `PackPool.Items4` / 第三档 Segmented / 三档映射全部回退） |
| 总览 `items[]` | 收集 `rarity in (4, 5, 6)`；**`[:20]` 上限删掉**——4★ 卡排在 6★/5★ 之后，截 20 张的话真实账号里 4★ 永远挤不进总览 |
| 4★ 卡样式 | 复用现有物品卡：紫色品质条（上一轮的三色口径）+ 次数文本；图标仍按需取图、缺图名称占位 |
| `_rare_history` | 保留按稀有度泛化（当前只喂 5★ 档），将来想再加分栏只差一行 tab |

## 四、备注

- 总览卡片计数文案由包侧给：`count` 从裸数字改为 `f"{n}次"`（Alpha：「不应是『1次』吗」）；provider 每调用一次新进程，改完重开抽卡页即生效，宿主无需重建。
