# 终末地设置页 · 分辨率预设（运行期枚举显示器模式）

日期：2026-11-16 · 范围：只动包内 `settings.cs`（宿主零改动）
（原文件名「22 档逐档对齐」，结论变了以后改名，git 里是同一个未跟踪文件）

## 结论

游戏的分辨率下拉**不是固定表**，而是本机显示器枚举出来的模式：`EnumDisplaySettings` 全量（含各刷新率）→ 按 宽×高 去重 → 宽降序、同宽再按高降序。

- 4K 屏 → 22 档，顶部 3840×2160（截图实测 22 档与此完全逐项逐序一致）
- 8K 屏 → 顶部直接是 7680×4320
- 所以「终末地支持 8K」是真的，但 4K 显示器上永远看不到 —— 不是游戏档位限制，是这块屏的 EDID 里没有这个模式

包内第一版把这 22 档写死，等于把「我这一台 4K 屏」钉进了代码：换 8K 屏 / 带鱼屏会缺档，8K 永远出不来。现已改为**运行期枚举**。

> **不补超采样档**（2026-11-16 已回退过一次）：一度追加过 `7680×4320 / 5760×3240 / 5120×2880` 三档"8K 私货"，被否 —— 宿主 `GameSettingService.FilterByMonitor` 的口径就是「只列显示器支持的模式，原生分辨率兜底」，设置页必须同一个口径；给用户一个选不了、写下去还可能起不来的档位没有意义。要用 8K，就走 VSR 让驱动真报出这些模式（那时枚举结果里自然有）。

### 和 Windows 显示设置的关系

同源，但**不是同一个界面**：

| | 数据源 | 过滤 |
|---|---|---|
| 游戏下拉 | 适配器模式全表（`EnumDisplaySettings`） | 只按 宽×高 去重，其余全留 |
| Windows 设置 → 显示 → 显示器分辨率 | 同一张表 | 只列与当前纵横比一致、且不超原生分辨率的常用档 |
| Windows 设置 → 高级显示 → 显示适配器属性 → 列出所有模式 | 同一张表，**原型** | 不过滤（每个刷新率 / 色深一行） |

证据：游戏列表里有 1920×1200、1280×1024、1600×1200 这些 16:10 / 5:4 / 4:3 档，Windows 设置的主下拉在 16:9 屏上根本不会给；要 1:1 对照，只能看「列出所有模式」。

新增模式（VSR / DSR / EDID 欺骗器）会**同时**出现在三者里，因为都取自驱动模式表。

## 本机实测（4K 屏，`EnumDisplaySettingsW` 输出）

```
3840×2160  3200×1800  3072×1728  2560×1440  2048×1536
1920×1200  1920×1080  1760×990   1680×1050  1600×1200
1600×900   1366×768   1280×1024  1280×960   1280×720
1152×864   1128×634   1024×768   800×600    720×480

```

原始枚举 408 个模式（同一分辨率按刷新率 / 色深重复多次），去重后正好 22 个，与游戏下拉逐项一致 —— 这条比对就是「列表来源」的证据，以后别再拿截图抄表。

## 实现要点

### 1. 枚举 + 回退

`DisplayModes()`：`EnumDisplaySettingsW(null, i, ref DEVMODE)` 循环到失败为止；按 `(w,h)` 去重、过滤 640×400 以下的噪声档、排序（宽降序 → 高降序）。枚举失败（远程桌面 / 无显示设备）回退 5 个常用档，保证下拉不空。

DEVMODE 按完整字段顺序声明（`StructLayout` + `ByValTStr`），只读 `dmPelsWidth` / `dmPelsHeight`；类型声明必须写在文件末尾（CS8803：顶级语句之后）。

### 2. 同宽档位靠「合成槽位」区分

宿主 `PackSettingsPage.BuildChoice` 只按 `option.value` 匹配行值：

```csharp
int index = row.Options.FindIndex(o => o.Value == row.Value);
```

option 值若直接用宽度，1920×1200 与 1920×1080 撞值 → 高亮错行、也分辨不出选的是哪档。

处理：行值改成 `宽×10000+高`（`Slot(w,h)`）只做匹配，真实写入交给 `option.writes`。`Stage()` 的执行顺序正好兜住：

```csharp
Stage(row, combo, value);              // pending[WidthKey] = 19200001200（临时）
foreach (var (name, write) in optionWrites) _pending[name] = write;  // 覆盖成 1920 / 1200
```

行值另挂了专属 `hint`，悬停不会露出合成值。

### 3. 预设同时写两套分辨率键

| 键 | 值 |
|---|---|
| `Screenmanager Resolution Width_h182942802` / `Height_h2627697771` | 档位宽 / 高 |
| `Screenmanager Resolution Use Native_h1405027254` | 0（清原生标志） |
| `video_resolution_width_h583690364` / `height_h2517654917` | 同一档位宽 / 高 |

`Use Native=0` 与宿主内置 `GameSettingPage.SetPgrResolutionSetting` 口径一致。

### 4. 下拉启用条件：只按「自定义分辨率」

终末地的全屏不锁分辨率（全屏 = 无边窗口铺满屏幕，渲染分辨率另算），所以预设下拉只按 `Use Native=1` 放开、宽高输入只按 `Use Native=0` 放开。选中档位不写 `Use Native`、也不动全屏模式。当前档位读 `video_resolution_*`（全屏时 Screenmanager 会被游戏改成桌面分辨率）。详见 `游戏包-画面设置-状态机与写入生效-交接.md`。

## 遗留

1. **4K 屏上想要 8K**：下拉不会给（只列显示器支持的模式）。要么开 VSR / DSR 让驱动真报出 8K 模式，要么勾「自定义分辨率」手填 7680×4320 碰运气 —— 后者显示器不支持该模式，游戏可能黑屏 / 建窗失败 / 自动回退，未实测。
2. **多显示器**：现在固定枚举当前显示器（`deviceName = null`）。游戏有 `UnitySelectMonitor` 键；若以后要按选中显示器枚举，需改用 `EnumDisplayDevices` 取 `\\.\DISPLAYn` 再逐台枚举。
3. **自定义宽高输入框不镜像 `video_resolution_*`**：宿主 `number` 控件只能写自己那一个键（`writes` 是静态字典，给不了「把本值同时写到另一个键」的能力）。预设走 option.writes 没问题，手填自定义尺寸只写 Screenmanager 一套。要修得给宿主加通用能力（如 `mirrorTo`）。

## 附：想看到 / 跑到 8K，三条路

| 路子 | 能进游戏下拉吗 | 能看到画面吗 | 说明 |
|---|---|---|---|
| **AMD VSR**（推荐） | 能 | 能 | Adrenalin 22.3.1 起驱动级超采样支持 5K / 8K（RX 5000/6000/7000）。AMD Software → 显示 → 开启「虚拟超级分辨率」，Windows 就给这块 4K 屏加虚拟高分模式 → 游戏下拉直接出现，8K 渲染后由驱动降采样回 4K。帧数按 8K 算，6750 GRE 只适合截图 / 看画质 |
| **8K HDMI 欺骗器** | 副屏时不能；设为主显示才行 | 不能 | 它是一块"假显示器"，游戏会在那颗 HDMI 头上以 8K 渲染，输出进欺骗器，屏幕上看不到（可用于无头串流）。且很多标称 8K 的欺骗器（如 Lindy 8K60）预置 EDID 最高只到 3840×2160 / 4096×2160，7680×4320 只在「克隆真实 8K 屏」时才出现 —— 插上先跑 `tools/list-display-modes.py` 验 EDID |
| **手填自定义宽高** | 不适用 | 不保证 | 勾「自定义分辨率」填 7680×4320 写进注册表；Windows 在 4K 屏上大概率拒绝这个 swapchain，游戏可能回退或建窗失败 |

验证工具：`Arietta-GamePacks/tools/list-display-modes.py`（在包目录外，不影响签名），逐台显示设备打印当前模式、模式条数、去重档位、是否支持 8K。
