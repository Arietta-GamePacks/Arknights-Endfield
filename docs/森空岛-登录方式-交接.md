# 森空岛 · 登录方式（Token / 短信 / 密码 / 扫码）- 交接

> 时间：2026-11-15
> 性质：包侧登录链实现——令牌（已有）、手机号短信（含极验 v3 滑块）、手机号密码、扫码四类，端点全在包内。
> **终态口径见 `森空岛模块-归档.md` 第十节**（登录框 UI 定稿）；本文件是过程与逐条实测记录。
> 前置：`docs/森空岛API-数据终端直连实测-交接.md`（token→cred 主链）、宿主 `Arietta/docs/游戏包-社区登录对话框-交接.md`（宿主 UI 与协议契约）。

## 一、背景

用户指令：「登录页太简陋，跟鸣潮一样，分 token 登录和手机号登录，注意看有没有滑块认证之类的」；随后追加「要做扫码登录吗」（确认要做）；再追加「验证码登录里面还要包括密码登录，那这样的话就不能叫验证码登录了」。

原有凭证只有一种拿法：浏览器登 `user.hypergryph.com` → 手动复制 `content`。

## 二、调查结论（鹰角通行证登录链，来自现役开源实现）

| 项 | 结论 |
|---|---|
| 发码 | `POST as.hypergryph.com/general/v1/send_phone_code`，body `{"phone","type":2}`（type=2=登录验证码），**免森空岛 sign** |
| 发码需滑块 | **可能**：风控命中返回 `status:1` + `data.captcha{gt,challenge,new_captcha}`（**极验 v3 云端模式**）；带 `captcha{geetest_challenge,geetest_validate,geetest_seccode}` 重发即过。`status:0` 则无需滑块 |
| 短信登录 | `POST as.hypergryph.com/user/auth/v2/token_by_phone_code` `{"phone","code"}` → `data.token` |
| 密码登录 | `POST as.hypergryph.com/user/auth/v1/token_by_phone_password` `{"phone","password"}` → `data.token`。**账号密码错误也回 200**，须看 `status`（0 才成功） |
| 扫码-建码 | `POST as.hypergryph.com/general/v1/gen_scan/login` `{"appCode"}` → `data.scanId`（+ `scanUrl`，兜底自组 `hypergryph://scan_login?scanId=<id>`） |
| 扫码-轮询 | `GET general/v1/scan_status?scanId=` → `status`：**0=confirmed / 100=pending / 101=scanned / 102=expired** |
| 扫码-换 token | `POST as.hypergryph.com/user/auth/v1/token_by_scan_code` `{"scanCode"}` → `data.token` |
| 与库街区滑块的差异 | 库街区是**极验 v4**（`initGeetest4`/captchaId）；鹰角是**极验 v3**（`initGeetest`/服务端下发 gt+challenge） |
| 四种方式的关系 | 拿到的 token 全是**同一个鹰角账号 token**（与浏览器 content 同物），凭证格式不变 |

参考实现（均公开、非本次逆向）：`baiqwerdvd/ArknightsUID`（发码+滑块）、`arkntools/arknights-toolbox`（扫码链+状态码最全）、`ArkMowers/arknights-mower`（密码登录）、`sklandplus/sklandplus`（密码登录错误语义）、`FrostN0v0/nonebot-plugin-skland`（扫码链）。

## 三、实现（包侧，游戏知识全在包内）

`skland.py`（皆免 sign，Header 带 Origin/Referer）：

- `send_phone_code(phone, captcha=None)` → `{ok, message, needCaptcha?, gt?, challenge?, newCaptcha?}`（不抛错）
- `token_by_phone_code(phone, code)` → token
- `token_by_phone_password(phone, password)` → token（账号密码错误也回 200，靠 `status` 判定）
- `qrcode_login_create()` → `{ok, scanId, url}`（`url` 交宿主渲染二维码）
- `qrcode_login_poll(scan_id)` → `{ok, state: pending|scanned|expired}`；confirmed 时在包内换好 token 返回 `{ok, state:"confirmed", credential}`

`provider.py` 的 `community-action` 新增动作（均在凭证前置检查之前，登录时尚无凭证）：
`login-send-code` / `login-phone` / `login-password` / `login-qrcode-create` / `login-qrcode-poll`。旧动作 `signin` 契约不变。

`credential.help` 改成 **Markdown 链接写法**（宿主渲染成可点超链接，不再裸露 URL）：
`登录[鹰角用户凭证](https://user.hypergryph.com)后，打开[账号信息页](https://web-api.hypergryph.com/account/info/hg)复制 content 到框内。`
宿主侧 `PackCommunityLoginDialog.BuildHelp` 先匹配 `[文案](url)`，裸 URL 仍照旧自动识别（对任何包通用）。

## 四、验证方式

- **离线探针**（不真发短信、不落敏感信息）：
  - `login-send-code{phone:"000"}` → `{ok:false, message:"手机号码有误"}`（端点/参数名正确）
  - `login-phone{phone:"000",code:"000000"}` → `{ok:false, message:"登录失败，手机号码或验证码错误"}`
  - `login-password{phone:"000",password:"x"}` → `{ok:false, message:"登录失败，账号或密码错误"}`（端点/字段名正确）
  - `login-qrcode-create` → `{ok:true, scanId:<32 hex>, url:"hypergryph://scan_login?scanId=…"}`（**真实建码成功**）
  - `login-qrcode-poll{scanId}` → `{ok:true, state:"pending"}`
- **未真打**：短信正规号会真发短信、滑块需风控命中；密码需真密码；`scanned/confirmed/expired` 分支需真机扫码。均已按参考实现的状态码与字段名实现。
- 部署副本已同步并重签：`valid · PaperKito`；包目录无 `__pycache__`。

## 五、已知待办

## 六、登录框 UI 调整（2026-11-15 用户指令）

三处改动：两处宿主通用能力 + 一处包内文案。

| 位置 | 改动 |
|---|---|
| 账号登录页签 | 删掉页签内的说明文字（原「验证码登录：短信可能因风控要求先完成滑块验证。」/「使用注册该账号时设置的密码登录。」两句）。滑块、错误提示仍走底部 `_textHint`，语义不丢。 |
| 扫码登录页签 | 二维码**画在对话框内**，不再弹独立窗口：内嵌 `WebView2`（220×220）+ 本地 `Assets/Lib/qrcode.min.js`，`NavigateToString` 离线渲染。尺寸**不许读 `window.innerWidth/innerHeight`**——`NavigateToString` 首次执行时视口还没完成布局，报的是默认大尺寸，二维码会画成控件的好几倍、被 `overflow:hidden` 裁成"只显示左上角"（2026-11-15 用户实测：首次显示异常、点「刷新二维码」后正常）。改为纯 CSS 自适应：`640×640` 像素源 + `#qr img{width:auto;height:auto;max-width:100%;max-height:100%}` + `#qr{aspect-ratio:1/1}`，任何视口都等比缩到框内，视口后变也自动跟随。窗口关掉时 `WebView2.Close()` 释放内核。 |
| Token 页签 | `credential.help` 改 Markdown 链接（见 §三），宿主渲染 `[文案](url)`。 |

顺带把 `Border.Child = 页签` 的反复换孩子改成三个页签常驻 `Grid`、只切 `Visibility`——二维码页是 WebView2，反复摘挂可视树会重建内核。

同批清掉包内孤儿 `assets/FatSlider.xaml`：宿主已移除 `DoubleRound2Converter/DoubleRound3Converter`，这份旧样式拷贝会被宿主 XAML 编译器扫到并报 `WMC0001`，且包内无任何文件引用它。删除后部署副本已重签。
