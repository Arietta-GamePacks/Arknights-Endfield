## 三、四列自适应

口径原文见 **`Arietta/docs/窗口-三档尺寸设置-交接.md` §四**：

> 卡池列宽：一屏固定 4 个。`(ViewportWidth - 48 边距 - 12×3 间距) / 4`，`floor` 后夹 `240~360`。
> 大 ≈315 / 中 ≈285 / 小 ≈265，正好铺满、第 5 个起在右侧横向滚动。
> **别改成按卡池总数等分**；`ViewportWidth` 优先，扣掉竖滚动条后算。

实现（与鸣潮 `GachaLogPage` 同款）：

- `PackPool.ColumnWidth`（可观察，默认 268）+ XAML `Border Width="{x:Bind ColumnWidth, Mode=OneWay}"`。

**为什么原来「左边空一片」**：卡片写死 268，4 张只占 1107，大档窗口可视宽约 1336，多出来的 ~200 全堆在**右侧**（左边只有 24 的设计边距，与标题左缘对齐）。截图里量到的实际边界：卡片 89→1196，窗口 1401。改等分后 → `(1336-48-36)/4 ≈ 313`，4 列铺到 1377，两侧都只剩 24。

## 七、附：GitHub 上终末地抽卡的取数方式调查（回答 Alpha 的提问）

### 7.1 数据源只有一个

所有项目最终都打同一组官方接口，**没有一家**是截图 OCR / 读内存 / 模拟点击：

```
GET https://ef-webview.hypergryph.com/api/record/char?lang=zh-cn&token=<u8_token>&server_id=1&pool_type=E_CharacterGachaPoolType_Special&seq_id=<游标>
GET https://ef-webview.hypergryph.com/api/record/weapon?...
GET https://ef-webview.hypergryph.com/api/record/char/meta      卡池 tab
GET https://ef-webview.hypergryph.com/api/record/weapon/pool    武器池列表
GET https://ef-webview.hypergryph.com/api/record/{char|weapon}/rerun-counts   官方累计寻访次数
GET https://ef-webview.hypergryph.com/api/content?pool_id=...   UP 名单
```

即**游戏内「寻访记录」页面自己用的那套 H5 接口**。国际服域名 `ef-webview.gryphline.com`，`server_id` 2=亚服 / 3=欧美服。

`zonai.skland.com`（森空岛 App 接口）**没有抽卡记录**，只有签到与数据终端（角色 / 危机合约 / 碑文 / 战争回响）——所以「森空岛抽卡」这个说法在实现层面是不成立的，森空岛只提供**账号身份**。

### 7.2 拿 `u8_token` 的三条路

| 路 | 做法 | 代表项目 |
|---|---|---|
| **A. 常规方式**（游戏内开一次寻访记录） | 客户端把页面 URL 写进 `%LOCALAPPDATA%Low\{Hypergryph\|Gryphline}\Endfield\sdklogs\HGWebview.log`，正则抓 `https://ef-webview.<provider>.com/page/gacha_...?u8_token=...&server_id=...` | `bhaoo/endfield-gacha`（桌面版「系统账号」）、`mtaanquist/gacha-url`、`daydreamer-json/ak-endfield-gacha-link-gen`、`xqf946/gacha-query` |
| **B. 账号令牌链** | 通行证 token → `as.hypergryph.com/user/oauth2/v2/grant`（appCode `be36d44aa36bfb5b`）→ `binding-api-account-prod.hypergryph.com/account/binding/v1/u8_token_by_uid` → `u8_token` | `FrostN0v0/nonebot-plugin-skland`、`qihang518887/astrbot_plugin_sklandv2`、`wahaha216/koishi-plugin-skland`、`bhaoo/endfield-gacha`（「添加账号」） |
| **C. 第三方中转** | 自己不实现，转发到别人的 API 服务（如 `end.shallow.ink`） | `TakesBot/nonebot-plugin-endfield` |

### 7.3 关键变化：1.1 之后 A 路已死

两个独立来源（`bhaoo/endfield-gacha` README 的 Note、vinking 的抓取笔记）都写明：**终末地 1.1 起 `HGWebview.log` 不再记录寻访记录链接**，社区脚本大面积失效，官方也不再认日志里的旧令牌（`gacha-query` 的说明是「有的机器上提示官方没有接受日志里的凭证」）。

所以现状是：**桌面端还能读日志（旧客户端/国际服），机器人只能走 B**。这也正好解释了为什么「绑社区账号」是唯一稳定方案——B 路要的就是那份账号 token，跟我们社区登录拿到的是同一个东西。

### 7.4 对本包的意义

- A 路保留为兜底（`gacha-url`），但**不能当主路径**；
- B 路就是现在的社区凭证，天生复用；
- 两条都试 = Alpha 要求的「同时走」，且天然覆盖「国服有 token 但日志没有」「国际服只有日志」两种情况。

## 八、第二批（同日晚）：速度 / 账号切换 / 设置面板

Alpha 反馈三条：「抽卡的设置都没了？」「更新记录太慢了我都不知道看他转了多久」「鸣潮的账号切换怎么没搬过来」。

### 8.1 为什么会慢到分钟级

接口 `fetch_pages` 每页只给 **5 条**（官方限制），并且原来是：

- **串行**：角色池 4~5 类 + 武器池 N 个，一个一个来；
- **每页 sleep 0.28~0.65s**；
- **没有本地缓存**：每次点「更新记录」都从最新翻到最早，800 抽 ≈ 160 页 ≈ 2 分钟起。

### 8.2 三层提速（包侧 `provider.py`）

| 手段 | 实现 |
|---|---|
| 本地缓存 | 原始记录按 **账号** 落盘：`<data_dir>/gacha-<uid>_<server>.json`（`data_dir` 由宿主传，= `gamepacks/arknights-endfield/`）。打开页面 `mode=cache` → **零网络请求**直接出图 |
| 增量补拉 | `mode=incremental`：用上次的 `max_seq_char/max_seq_weapon` 作 `stop_seq`，`seqId <= stop` 即停（seqId 账号内单调递增、列表新到旧）。已同步过的账号通常**每池 1 个请求** |
| 并发 | `ThreadPoolExecutor(8)`：池子清单并发取，**各卡池并发翻页**；页间 sleep 降到 0.04~0.1s |

`mode` 三档：`cache`（打开页面，**只读盘**，没缓存就回 `needsSync`，绝不联网）/ `incremental`（更新记录）/ `full`（全量重拉）。
合并走 `merge_pools()`：按 `seqId` 去重，缓存老记录 + 新拉到的记录取并集，不会因为增量把历史丢掉。

> **2026-11-16 修正（Alpha：「不用打开就同步啊，肯定是手动的」）**：
> 第一版 `cache` 在没有缓存时会退化成 `full`，等于一打开页面就自动全量拉；现在还顺手自动读 `HGWebview.log`。
> 两处都改掉了：
> 1. `cache` 缺缓存 → 直接回 `{"needsSync": true, "syncHint": ...}`，宿主画「点更新记录同步一次」的空态，**一个网络请求都不打**（为了做到这点，缓存文件名从「uid_server」改成「凭证 sha1 前 16 位」——uid 本身要联网才换得出来；`load_only_cache()` 兜底：目录里只有一份缓存时直接用）。
> 2. 宿主 `LoadAsync(mode)` 只在 `mode != "cache"` 时才 `EnsureLogTokenAsync()` 读日志；打开页面、切换账号都走 `cache`，**不碰本机文件**。
>
> 结论：**联网只在用户点「更新记录 / 全量重拉 / 从游戏日志读取」时发生**，其余一律读盘。

### 8.9 uid 口径修正（Alpha 2026-11-16：「这是明日方舟的 UID 吧？我们是终末地」）

**上一版取错字段**：`bindingList[].uid` 是**鹰角通行证账号级 uid**（和明日方舟共用同一个数字），不是终末地 UID。
终末地 UID = **`bindingList[].roles[0].roleId`**（森空岛 App 个人主页显示的那个数字，`card/detail` 的 `base.roleId` 同值）。

| 位置 | 修法 |
|---|---|
| `provider.resolve_credential` | 返回值 `uid` 改成 `roles[0].roleId`（缺省回落账号 uid）；**`u8_token_by_uid` 请求体仍用 `bindingList[].uid`**（该接口要的是账号级 uid，不能跟着改）；额外返回 `role_id` |
