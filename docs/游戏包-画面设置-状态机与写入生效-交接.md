# 画面设置：分辨率状态机 / 画质预设「自定义」/ 写入到底有没有用

日期：2026-11-16 · 范围：包内 `settings.cs` + 宿主两处通用能力（`uiOnly` / `mirrorTo`）

## 1. 分辨率状态机（终末地和鸣潮不一样）

**全屏下也能选预设分辨率。** 终末地的「全屏」= 无边框窗口铺满屏幕，渲染分辨率是另一回事：游戏里"2K 全屏"的实机状态就是 `Screenmanager = 3840×2160`（桌面）+ `video_resolution = 2560×1440`（渲染）。所以预设下拉不该被全屏锁住 —— 这条被用户实测纠正过一次（2026-11-16 01:25）。

唯一开关是「自定义分辨率」：

| 自定义分辨率 | 预设下拉 | 宽高输入 |
|---|---|---|
| 不勾 | **可交互** | 灰 |
| 勾上 | 灰 | 可编辑 |

- 全屏不勾 + 自定义不勾 → 选预设 = 开一个该尺寸的窗口（「全屏」取消时写 `video_full_screen = 0`）
- 全屏勾着 + 自定义不勾 → 选预设 = 全屏但按该分辨率渲染

**「自定义分辨率」不是注册表键，是算出来的**（2026-11-16 实测纠正）：窗口模式下 `Screenmanager Resolution Use Native` 必然是 0，它不是"自定义"标志；游戏里也没有任何"我是自定义"的持久键 —— 游戏和 Arietta 内置设置页都是**看当前宽高在不在档位表里**。

落地用的是宿主新增的通用能力（`游戏包-设置页通用渲染器-交接.md`）：

- **`uiOnly` 行**：包把 `isCustom`（当前宽高不在枚举档位里）算好传给宿主，键名 `ui:custom-resolution`；勾选只切「下拉 / 手填」，不写注册表，应用时跳过。
- **`mirrorTo`**：宽高输入同时写 `video_resolution_*`（原来只写 Unity 镜像键，重启就被游戏覆盖 —— 手填其实一直没生效）。

条件：`presetRow.enabledWhen = [ui:custom-resolution = 0]`、宽高输入 `= [ui:custom-resolution = 1]`。

### 当前档位要读 `video_resolution_*`，不是 Screenmanager

实测（2026-11-16 01:25，在 Arietta 里应用 2560×1440 后启动游戏）：

| 键 | 值 | 谁写的 |
|---|---|---|
| `video_resolution_width/height` | 2560 / 1440 | Arietta 写的，游戏启动后保留 → **游戏认这一套** |
| `Screenmanager Resolution Width/Height` | 3840 / 2160 | 被游戏在全屏启动时改回桌面分辨率 |
| `Screenmanager Resolution Window Width/Height` | 2560 / 1440 | 游戏自己同步的窗口尺寸 |
| `video_full_screen` / `Screenmanager Fullscreen mode` | 1 / 1 | 全屏 |

结论：游戏自己的设置层是 `video_*`；Unity 的 `Screenmanager *` 是运行时镜像，全屏时会被覆盖。所以页面「当前档位」必须读 `video_resolution_*`（读不到再退回 Screenmanager），否则全屏 2K 会显示成 4K。

## 2. 画质预设的「自定义」档

`video_custom_quality = 1` 时游戏下拉显示「自定义」。之前我们的页面没有这一档，`video_quality_main = 4` 直接显示「低」—— 与游戏所见不一致。

现在下拉是 6 项：`自定义 / 极高 / 高 / 中 / 低 / 极低`。

- `custom = 1` → 行值按 0 处理，高亮「自定义」
- 选「自定义」→ 只写 `custom = 1`，底层 `main` 原样保留
- 选具体档位 → 写 `main = 档位值` + `custom = 0`
- 改任意画质细项 → 已有逻辑自动写 `custom = 1`（联动与游戏一致）

> 档位枚举 `1=极高 2=高 3=中 4=低 5=极低` 来自 Collapse 插件目录 + 本机实测值（`main=4`），**没有在游戏 UI 里逐档核对过**。要定案：游戏里逐个切预设、退出，读 `video_quality_main` 看变几。

## 3. 写注册表到底能不能改画面

能，机制是这样的：

- `HKCU\Software\Hypergryph\Endfield` 下这些 `xxx_h1234567890` 键就是 **Unity PlayerPrefs**（`键名_h哈希` 是 Unity 在 Windows 上的存储格式）。
- 游戏启动时读 PlayerPrefs → 应用；游戏内改设置时写回同一批键（本机 `main=4`、`custom=1`、`effect=3000` 都是它自己写的，双向可证）。
- 参考实现 `Hi3Helper.Plugin.Hypergryph` 的说明原文：**「关闭游戏后应用，下次启动生效」**（`EndfieldPreferenceCatalog.cs:75`）—— 第三方也是这么改的。

三条硬约束：

1. **游戏必须关着**（运行中改会被它退出时的回写覆盖）。
2. **个别项被游戏校验会回退**（比如显示器不支持的分辨率）。
3. 有的设置是"启动时读一次"，有的是"进设置页时刷新"，改完必须重启游戏才看得到。

### 已知缺口

| 缺口 | 影响 |
|---|---|
| ~~「全屏」勾选框只写 `Screenmanager Fullscreen mode`~~ **已修**：改绑 `video_full_screen_h1998742411`（1 全屏 / 0 窗口） | 之前写的是 Unity 运行时镜像，游戏启动会按自己的 `video_full_screen` 回写，所以「取消全屏」不生效。现在取消全屏 = `video_full_screen=0` → 游戏以窗口模式启动，窗口尺寸取 `video_resolution_*`（上面选的预设） |
| 窗口尺寸键 `Screenmanager Resolution Window Width/Height` 我们不写 | 实测游戏自己会把它们同步成 `video_resolution_*`（本次 2560×1440），不需要我们写 |
| ~~「自定义」宽高输入不镜像 `video_resolution_*`~~ **已修**：宿主加 `mirrorTo`，手填宽高同时写 `video_resolution_*` | 之前手填只写 Unity 镜像键，重启就被游戏覆盖 —— 等于没生效 |

第一条要修得给宿主加通用能力：`check` / `toggle` 的 `writes` 目前是静态字典，表达不了「勾上写 1、取消写 0」两条不同 target。按红线这属于可加的通用能力（换游戏包宿主也不用改）。

### 验证配方（两分钟）

1. 关游戏 → Arietta 设置页把「帧率上限」改成 `30 FPS` → 应用 → 启动游戏
2. 游戏里看帧率是否锁 30；同时退出后再读一次注册表，确认 `video_frame_rate_8 = 3000` 没被游戏改回
3. 若生效 → 写入链路通；若不生效 → 说明游戏还读了别的存储（启动器配置 / 游戏内配置文件），再往下挖
