# 游戏包-背景主题色声明-交接

## 现象

包里已经有 `assets.background`（`background.webp`），主页也能铺出来，但「从背景取主题色 →
改按钮/开关颜色」这条链路看起来没生效：按钮始终不是终末地的品牌黄。

## 实测结论：链路没坏，是**取出来的颜色错了**

`BackgroundGallery.Resolve` → `MainView.LoadCustomBackground` → `BackgroundAccentService.Apply`
→ `BitmapDecoder` → `AccentColorHelper.GetAccentColor` → `ApplyAccentColor` 全链路正常，
webp 解码也没问题。修复前日志（`src/Arietta/log/Arietta_261115.log`）：

```
01:17:30  Background accent color #FF477AB2 (from ...\background.webp, cache=False);
          AccentFillColorDefaultBrush=#FF90AFD0; AccentTextFillColorPrimaryBrush=#FFB5C9E0
```

`#FF477AB2` 是蓝灰，不是终末地主题色。用 Python 复刻 `AccentColorHelper` 的 24 桶色相投票
（缩到 128 宽、隔点取样、S≥0.25 / V∈[0.15,0.92]、S×V 加权）得到同样的结果：

| 色相桶 | 票数 | 对应画面 |
|---|---:|---|
| 210–225° | 23.33 | 蓝灰角色/衣料 |
| 195–210° | 22.43 | 蓝灰角色/衣料 |
| 60–75° | 18.92 | 品牌黄绿块 |
| 45–60° | 16.09 | 品牌黄绿块 |

赢桶 ±1 桶圆周平均 → **色相 211°，强调色 `#477BB2`**，与日志一致。
主视觉是白灰底 + 大面积蓝灰角色（约 202 个取样像素），品牌黄只占小面积高饱和块（约 17 个），
而且黄色被 15° 桶切到两个桶里各自投散，所以「画面最大块主色」算法必然选蓝。

结论：**这类主视觉不适合自动取色**，要由包自己声明主题色；硬改取色算法会连带影响鸣潮/战双
所有背景，不做。

## 实现行为

### 宿主侧（Arietta，通用 schema，不含任何游戏知识）

新增 `assets.accentColor`（hex：`#RGB` / `#RRGGBB` / `#AARRGGBB`），包声明时宿主直接用它，
跳过图片取色；字段缺失或写错时静默回落到原来的按图取色，**旧包行为不变**。

| 文件 | 改动 |
|---|---|
| `src/Core/GamePack.cs` | `GamePackAssets` 新增 `string? AccentColor` |
| `src/Features/Background/AccentColorHelper.cs` | 新增 `ParseColor(string?)`，无效值返回 null |
| `src/Features/Background/BackgroundGallery.cs` | `BackgroundItem` 新增 `Color? DeclaredAccent`；包自带背景项从 `pack.Assets.AccentColor` 解析赋值 |
| `src/Features/Background/BackgroundAccentService.cs` | `Apply(路径, DispatcherQueue, Color? declaredAccent = null)`：声明色优先、不进图片取色缓存；日志来源写 `pack-declared accent` 便于排查 |
| `src/Features/ViewHost/MainView.xaml.cs` | 静态图 / 视频两处 `Apply` 都把 `item?.DeclaredAccent` 传下去 |

强调色的应用链路（`ApplyAccentColor` 写 `SystemAccentColor*` + `WindowEx.ChangeAccentColor`
主题对折）一行没动，所以按钮、开关、超链接、启动按钮底盘照旧一起变色。

### 包侧（本仓库）

`game.json` → `assets` 增加：

```json
"accentColor": "#E6D800"
```

色值取自包图标亮黄区众数 `(216,208,0)` 与背景亮黄块 `(248,248,48)` 之间，取 `(230,216,0)`
作为终末地品牌黄；想换色只改这一行。

- 同一字段已同步到部署副本 `Arietta/src/Arietta/games/arknights-endfield/game.json`。
- 部署目录已用 `tools/GamePackSign` 重签（`sign` + `verify` → `valid`）。
- **仓库根的 `signature.json` 按 AGENTS.md 约定等 assets 半成品收尾统一重签**，本次未动。

## 验证

- 构建宿主：`dotnet build Arietta.csproj -c Release` → **0 错误 / 26 个既有警告**。
  首次构建只报 `MSB3026/MSB3027/MSB3021`（开发实例锁住 `Arietta.exe`），按项目约定结束实例后
  复建通过；无 CS/WMC 错误。
- 真跑实例（当前游戏为 `External:arknights-endfield`）后的日志：

```
01:22:48  Background accent color #FFE6D800 (from pack-declared accent, cache=False);
          AccentFillColorDefaultBrush=#FFF0E766; AccentTextFillColorPrimaryBrush=#FFF5EF99
```

  即 `AccentFillColorDefaultBrush`（启动按钮底盘 / `AccentButtonStyle` 按钮底色）已从修复前的
  冷蓝 `#FF90AFD0` 变为黄色系 `#FFF0E766`，文字强调色同步变黄。

## 边界与待办

- 声明色**只挂在包自带背景这一项**上：用户主动换成本包里其它自定义背景时，仍按那张图取色，
  不再强制品牌黄（符合「背景主题色跟着背景走」的语义）。
- 包背景以后改成视频也一样生效（视频分支同样传声明色），不需要额外海报图。
- 改 `game.json` 任何字段后，部署副本要重签，否则包显示「作者未验证」。
- 若将来希望「无论选哪张背景都用品牌色」，把 `DeclaredAccent` 从 `GetItems` 的包背景项挪到
  `Resolve` 的当前条目级即可，宿主仍是通用逻辑。
- 宿主的公开仓库导出（去注释 + `commit.bat`）**未执行**：按项目发布流程需人工确认增量后提交，
  本轮只做到主仓库构建通过 + 开发实例实跑验证。
